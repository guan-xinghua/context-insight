# 多人服务器部署（每用户单实例）— 需求

## 背景

insight 当前是**单机单实例**工具：一台机器一个实例、一个库、一个固定端口（21025）。
团队需要在**一台服务器上多人使用**（≤5 人）：每人 SSH 登录自己的系统账号，各看各的会话数据。

历史上为治「每次关闭残留进程」（next-server / smart-agent 存活半天的实测事故），
2026-09-21 做过「单实例收口」：start.sh 杀旧重启、固定绑 21025、绝不端口漂移。
多人化必须保留这套清理语义，不能把病根带回来。

## 需求

| # | 需求 | 说明 |
|---|------|------|
| R1 | 多人隔离 | 服务器上每人一个 insight 实例，数据/配置/凭据完全隔离，互不可见 |
| R2 | 共享视角不新增 | 团队共享数据由数据湖（lake 链）承担——湖本来就是共享设计，insight 侧不建共享库 |
| R3 | 关闭即零残留 | **随会话语义**：Ctrl+C / 终端关闭 / SSH 断开，实例及其全部子进程（next、smart-agent）当场清干净；不依赖「下次启动再扫」 |
| R4 | 工具链零配置对准 | cpx 自动导入、cbi（CLI/TUI）默认连接，自动找到**当前用户自己的**实例，不需要每人手工配地址 |
| R5 | 单人本机零感知 | 不部署多人场景的个人用户，升级后行为完全不变（默认端口/默认路径/默认清理语义） |
| R6 | 不开网络面 | 服务保持绑 127.0.0.1；远程访问走 SSH 隧道。**不做鉴权体系**（API 无鉴权 + import-file 接受任意路径，开网络面 = 裸奔） |

## 非目标（明确排除）

- ❌ 单实例多用户（账号体系 / 行级隔离 / per-user 分库路由）——「互相看会话」不是需求，共享由湖承担
- ❌ 鉴权 / 登录 / token——不开网络面就不需要
- ❌ 常驻服务（systemd / daemon）——用户拍板**随会话语义**：会话/终端结束即关闭；要常驻自己用 tmux 挂着（HUP 语义天然组合：kill tmux session = 会话结束 = 清理）
- ❌ DB 默认位置改动——每人一份 checkout 各自 `prisma/dev.db` 已天然隔离；HOME 化留给未来（防 git clean 手滑）
- ❌ 实例管理面板 / 自动端口分配——端口人为约定固定值（自动分配 = 端口漂移 = 单实例收口明确拒绝过的方向）

## 规模与形态假设

- ≤5 人；每人一个系统账号（各自 HOME）+ 一份 git checkout
- 升级方式：每人 `git pull && ./start.sh -u`（既有产品化路径，不新增运维面）
